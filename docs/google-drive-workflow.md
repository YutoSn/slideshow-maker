# 作業手順書：Google Drive経由での写真連携

**対象プロジェクト**: slideshow-maker（音楽同期フォトスライドショーWebアプリ）
**作成日**: 2026-08-18
**背景**: 当初Google Photos連携を検討したが、Library APIの2025年仕様変更により自動的なライブラリ全体アクセスが不可（Composio経由ではアプリ作成データのみ取得可）。Picker API方式は都度手動選択が必要なため非効率と判断し、Google Drive経由での写真管理に方針変更。

---

## 1. 前提条件（設定済み・作業不要）

以下は既に接続確認済みのため、追加のセットアップは不要です。

| 環境 | 接続方式 | 状態 |
|---|---|---|
| Claude Code | Google Drive ネイティブコネクタ | ✅ 接続済み（11ツール利用可） |
| Claude Desktop / claude.ai | claude.ai Google Drive コネクタ | ✅ 接続済み |

Composio経由で設定した`composio`（Google Photos用）は、今回のフローでは使用しません。不要であれば以下で削除できます（任意）。

```powershell
claude mcp remove composio
```

## 2. Google Drive側の準備

### 2-1. 専用フォルダの作成

写真がプロジェクト用と個人利用のものが混在しないよう、専用フォルダを新規作成します。

1. Google Driveをブラウザで開く（drive.google.com）
2. 新規フォルダを作成し、名前を `slideshow-maker-photos` などわかりやすい名前にする
3. スライドショーで使いたい写真をこのフォルダにアップロード（サブフォルダで撮影日やイベント単位に分けると管理しやすい）

推奨フォルダ構成例：
```
slideshow-maker-photos/
├── test-images/        ← 開発・動作確認用のサンプル写真
├── 2026-08_夏休み/       ← イベント単位のサブフォルダ
└── 2026-07_誕生日/
```

### 2-2. フォルダIDの確認方法

ブラウザでフォルダを開いたときのURLに含まれる文字列がフォルダIDです。

```
https://drive.google.com/drive/folders/【この部分がフォルダID】
```

このIDを控えておくと、Claude Codeに「このフォルダの中身を見て」と指示する際にスムーズです（フォルダ名指定でも動作します）。

### 2-3. 対応フォーマットの確認

- 静止画：JPEG、PNG推奨（スライドショー素材として一般的）
- 動画ファイルはスライドショー素材としては対象外（音楽同期・セグメント調整は静止画前提のため）

---

## 3. Claude Code側での動作確認

`slideshow-maker`フォルダでClaude Codeを起動し、以下のような指示で動作確認します。

### 3-1. フォルダ内のファイル一覧を取得

```
Google Driveの「slideshow-maker-photos」フォルダの中身を一覧表示して
```

### 3-2. 特定ファイルの内容を確認・ダウンロード

```
「slideshow-maker-photos/test-images」フォルダの写真を確認して
```

### 3-3. 期待される結果

- フォルダ内のファイル名・更新日時・ファイルIDなどが一覧で返ってくる
- 個別ファイルの内容取得（プレビューやダウンロード）ができる

もし「フォルダが見つからない」等のエラーが出た場合は、フォルダ名のスペルやフォルダIDを再確認してください。

---

## 4. 運用フロー（slideshow-makerプロジェクトでの想定利用）

### フェーズA：開発・テスト用途（当面はこちら）

1. `test-images`フォルダにサンプル写真を数枚アップロード
2. Claude Codeにフォルダ内容を取得させ、アプリのビート検出・セグメント調整ロジックの動作確認に使う
3. 必要に応じてClaude Codeにローカル環境（`/home/claude`等）へダウンロードさせ、開発中のアプリに読み込ませてテスト

### フェーズB：アプリ本体への組み込み（将来検討事項）

現状のslideshow-makerはブラウザ完結型（Vite + React/TypeScript）の設計のため、Google Drive連携を本番機能として組み込む場合は以下の検討が必要です。

- ブラウザから直接Google Drive APIを呼ぶ場合、別途OAuthクライアント設定とフロントエンド側の認可フローが必要（現在Claude Code/Desktop用に設定したコネクタとは別物）
- 単純に「ローカルファイルを選択してアップロード」というUIのままにし、Google Drive連携は開発時のみ使う、という割り切りも選択肢

この部分は現時点では未確定のため、アプリのUI設計が固まった段階で改めて方針を決めるのがよさそうです。

---

## 5. 注意事項

- **大量ファイル取得時**：一度に大量のファイル一覧やダウンロードを指示すると時間がかかる場合があるため、フォルダを分けて段階的に指示するのが無難
- **プライベート写真の取り扱い**：家族・お子様が写っている写真をアップロードする場合、フォルダの共有設定（誰が閲覧できるか）を必ず確認する。デフォルトは「自分のみ」だが、リンク共有設定を誤ると第三者に公開される可能性がある
- **ファイル形式変換**：Google Driveは一部ファイルをGoogle独自形式に自動変換することがあるが、画像ファイル（JPEG/PNG）は対象外なので通常は問題なし
